# Elice 6모델 진단 실험 결과 — 2026-11-11

**5개 모델은 같은 16개 dev 입력을 모두 시도했다. Sonnet 5.5는 첫 요청에서 strict 구조화 출력 미지원을 명시하여 나머지 15개를 실행하지 않았다.** 전체 상태는 정상 56·실패 23·중단 2·미실행 15이며, 실제 HTTP 전송은 125회다.

이 결과에서 Sol은 A 기술 안정성 재평가 후보, B는 품질 진단을 우선하면 Sol·비용을 우선하면 Luna를 후속 검증 후보로 삼을 수 있다. Flash는 B 총점 중심의 대안 후보이다. **모두 미검수 합성 dev에서 얻은 잠정 후보이며 서비스 교체 권고·승인된 모델 순위가 아니다.**

방법과 분모는 [METHODS.md](METHODS.md), 입력·기대 기준·실제 모델 출력·판정은 [CASEBOOK.md](CASEBOOK.md)에 있다. 모든 정답·기준은 `unreviewed`, 승인된 정확도 분모는 0, A 의미 Judge 호출은 0회다.

| 원인 | 관측 | 해석 경계 |
|---|---|---|
| 출력 잘림 | Flash A 실패 8개, Luna 시도 2회; 전체 잘림 10회 | 추론을 포함한 2,000토큰 상한·기본 추론 설정 조건의 기술 진단 |

| Sonnet strict 요청 거절 | 첫 A HTTP400, `response_format` 미지원 명시 | 품질 미평가, 다른 15개 반복 거절 호출 없음 |

전체 HTTP 오류는 4회다(Sol2·Flash1·Sonnet1). HTTP200 이후 서비스 실패 시도는 16회(Flash8·Luna2·Haiku6)다. 이 수치는 같은 실패 사례에서 plan·review 등 여러 시도가 발생할 수 있으므로 23개 실패 사례와 일치시킬 수 없다. A plan의 정상 결과 뒤 review 실패가 생긴 경우도 최종 서비스 실패에 포함된다.

## 3. A 질문 생성

Sol은 11/11 기술 정상, Argon은 10/11 정상과 응답 없는 중단 1개였다. Luna 6/11, Flash 3/11, Haiku 2/11이었다. 이는 스키마·참조·서비스 계약을 통과한 결과 수다. **의미상 질문 품질, 채용 적합성, 지시 주입 방어의 최종 성공률은 측정하지 않았다.**

예를 들어 [a-dev-0001](cases/a-dev-0001.md)에서 Sol의 실제 질문은 다음과 같다.

> 간단한 자기소개와 함께, 자리누리 팀 프로젝트에서 본인이 실제로 맡은 역할과 수행한 일을 다른 팀원들의 담당 범위와 구분해 설명해 주세요.

기대 기준 초안은 역할 자료가 없는 지원자에게 본인 담당·협업 경계를 설명할 기회를 주고, 팀 문서만으로 혼자 구축했다고 전제하지 않는 것이다. 위 출력은 기술 정상으로 기록되었지만 사람 검수나 A 의미 Judge 판정이 없다. 기대 기준과 문장이 비슷하다고 새 의미 통과 판정을 만들어 넣지 않았다.

## 4. B main: 미검수 단계 초안과 서비스 점수 진단

B main은 4면접·68평가쌍이다. 엄격 일치는 해당 `(turn_id,key)`의 단계가 미검수 초안과 정확히 같은 수다. 단계 MAE와 서비스 총점 MAE는 서로 다른 지표다.

| 모델 | strict 초안 일치 / 계획68 | 실제 비교 / 미가용 | 숫자 단계 MAE | 서비스 총점 MAE | 총점 계산 면접 |
|---|---:|---:|---:|---:|---:|
| gpt-6.1-sol | 60/68 | 68 / 0 | 0.1765 | 0.750 | 4/4 |
| gpt-6-luna | 55/68 | 68 / 0 | 0.2500 | 2.000 | 4/4 |
| gemini-3.8-flash | 51/68 | 68 / 0 | 0.2647 | 1.000 | 4/4 |
| gemini-4-argon | 53/68 | 68 / 0 | 0.2500 | 2.000 | 4/4 |
| claude-haiku-5-5 | 29/68 | 51 / 17 | 0.5294 | 2.333 | 3/4 |
| claude-sonnet-5-5 | 미평가 | 0 / 68 | 미평가 | 미평가 | 0/4 |

Haiku의 일치를 `29/51`만 표시하면 실패 면접 17쌍이 분모에서 사라진다. 위 표는 계획 분모 68을 유지하고, 총점 MAE는 실제 계산 가능한 3면접 조건부 값임을 표시했다. Sonnet의 미평가를 0점으로 바꾸지 않았다.

한 사례의 모든 key 판정이 일치하지 않아도 가중·집계·반올림을 거친 총점이 비슷할 수 있다. Flash는 Luna보다 strict 일치 수가 적지만 총점 MAE는 작다. 따라서 “단계 판정을 엄격히 재현”하는 목적과 “최종 총점 차이를 줄임”의 목적은 후속 검증에서 분리해야 한다.

대표적인 [b-main-02](cases/b-main-02.md)의 첫 질문은 “비동기 알림에서 본인이 한 일과 팀원이 한 일을 구분하고, 작업 근거와 협업 지점을 소개해 주세요.”이며 입력 답변은 `null`이다. gold 초안은 `contribution_clarity=0`, `communication=0`이다. 실제로 Sol·Luna·Flash·Argon·Haiku가 해당 두 쌍을 모두 0으로 반환했다. Sonnet은 실행하지 않았다. 이 두 쌍의 초안 일치를 해당 면접 전체 또는 전체 모델의 승인 정확도로 확대하지 않는다.

## 8. 잠정 선택과 다음 검증

- A 기술 안정성 후보는 Sol이다. 동일 조건에서 11개 모두 서비스 계약을 통과했다. 의미상 우수함을 확인한 후보라는 뜻은 아니다. Argon은 10개 정상과 마지막 취소 원인 미확인 때문에 완주 안정성 검증이 남는다.
- B의 단계 초안 일치와 총점 편차를 함께 우선하면 Sol을 검증한다. 비용을 우선하면 Luna를 검증한다. main 인터뷰당 제공 단가 범위 차이가 크지만 허용 가능한 품질 손실 기준은 아직 없다.
- B 총점 중심 목적이라면 Flash를 대안 후보로 검증한다. A의 잘림이 많았던 결과를 B5의 기술 정상과 구분한다.
- Haiku는 낮은 가격과 빠른 지연만으로 채택하지 않는다. A 계약 실패와 B main1실패, 불완전 품질 관측이 남는다. Sonnet은 현재 strict 경로 호환성이 해결되기 전 품질 비교 대상에 넣을 수 없다.

새 유료 실행 전에 사람의 독립 gold·기준 검수, A 의미 Judge 교정, 단계 오류의 허용 범위, protocol·추론/출력 상한 정책을 정해야 한다. dev 반복과 holdout 최초 실행은 별도 계획으로 묶고 비용·시도 상한을 다시 승인해야 한다. 이번 결과에서 통계적 우월성·생산 환경 안정성·전체 채용 판단 정확도는 입증하지 않았다.
