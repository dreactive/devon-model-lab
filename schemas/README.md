# Schema exports

These exports describe only the unreviewed stage 1 smoke inputs. They do not
establish corpus coverage, reviewed labels, model quality, or a paid execution path.

Regenerate from this lab directory with the original DEVON checkout:

```powershell
.\.venv\Scripts\python.exe -B tools/export_schemas.py --devon-root C:\Users\dreac\Desktop\kdt\devon --output schemas
```

The helper sets `sys.dont_write_bytecode` before importing DEVON, imports the
original AI package through its source path, never imports backend Settings or
the seed database module, and refuses output inside DEVON or outside model-lab.
It overwrites generated schema files to permit deterministic regeneration; run
artifacts use separate entry points and collision rules.

The source-owned output schemas are generated by their original functions:

- `director-plan.q-lab-smoke-0001.v1.schema.json` uses the bounded Director v8
  plan schema for the actual first HR context, including coverage keys and the
  actual permitted source identifiers.
- `director-review.schema.json` uses the original review schema.
- `report-score.schema.json` uses the original score task output schema.
- `answer-analysis-v6.b-lab-smoke-0001.turn-1.schema.json` uses the original v6
  wire schema with the first report turn's required-point keys and original
  answer-unit segmentation. This is an export context from the existing smoke
  interview; no additional runnable answer-analysis case was created.

`question-input.schema.json` and `report-input.schema.json` are strict lab
envelope schemas. Original dataclass fields supply structural nested contracts;
the report envelope additionally describes the BE-to-AI field names. In this
stage the report envelope supports null analysis and parent fields, and empty
evidence and tool-result arrays. Unsupported material is rejected rather than
silently discarded. Top-level, payload, service-input, and nested object extras
are rejected, including expected labels accidentally placed in model input.
The service's original constructors and validators still enforce semantics,
including reference validity, candidate-key coverage, the complete rubric, and
supplemental source contracts. A JSON Schema pass does not replace those checks.

`gold.schema.json` validates the separate manual gold array. `review.schema.json`
validates the separate `{case_id, version, review}` metadata; the review remains
unreviewed, authored by Codex, with no reviewer or review date. Gold is an author
draft for smoke wiring, never a model response or independently reviewed truth.

`provenance.json` records SHA-256 hashes for original schema code, active prompt
files, both smoke inputs, and the rubric source. All 30 rubric phrases in the B
input are extracted as literal data from the `SCORE_CRITERIA` assignment using
Python AST inspection and `ast.literal_eval`; no seed function or SQL runs.
Regeneration verifies fixture rubrics exactly match those original literals.
The prompt path flags identify the original v8/v6/v3 source files used for this
export context; changing task versions requires deliberately updating the
generator choice rather than treating a filename as a schema version switch.
